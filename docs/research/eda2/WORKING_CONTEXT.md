# EDA2 — постоянный рабочий контекст

Этот документ фиксирует обязательные правила выполнения EDA2. Его нужно читать перед началом каждого нового блока и при восстановлении контекста после перерыва.

## Принятое решение

Пользователь согласовал последовательное выполнение семи блоков из [плана EDA v2](../eda/EDA_V2_PLAN.md). Работа ведётся блок за блоком, без самовольного расширения объёма.

## Вычислительный стек

- **NumPy** — основной инструмент численных расчётов: векторизация, массивы, статистические операции, матричная алгебра.
- **Numba** — применять точечно для особо тяжёлых циклов, которые нельзя эффективно выразить через NumPy или где NumPy-векторизация не даёт ускорения / требует чрезмерной памяти.
- Не использовать Numba «на всякий случай»: сначала выбирать естественную векторизацию NumPy.
- Чистый Python оставлять для управляющей логики и небольших операций.
- Не добавлять тяжёлые зависимости без необходимости.

## Жёсткая граница: не возвращаться к бесконечной очистке данных

Существующая скорректированная дневная панель PIT TOP50 является рабочей основой EDA2.

Запрещено без конкретной причины:
- повторно скачивать или перестраивать датасет;
- проводить общий аудит качества данных;
- повторять проверки пропусков, целостности и согласованности, которые уже выполнялись;
- создавать дополнительные циклы «проверки проверок»;
- откладывать статистическое исследование ради косметического улучшения чистоты датасета.

Допустимо исследовать конкретную проблему данных только если показано, что она непосредственно блокирует текущий расчёт или способна исказить конкретный результат. В таком случае:
1. назвать конкретный затронутый расчёт и механизм искажения;
2. выполнить минимальную адресную проверку или исправление;
3. вернуться к текущему исследовательскому блоку.

Наличие пропуска само по себе не является основанием останавливать исследование или запускать общий аудит.

## Организация блоков

Порядок:
1. Геометрия распределения доходностей.
2. Временная зависимость.
3. Межбумажная зависимость и совместное движение.
4. Поперечный разброс и breadth-статистики.
5. Неоднородность масштаба и волатильности.
6. Динамика PIT membership и мобильность рангов.
7. Торговая активность, концентрация и описательная условная структура.

Для каждого блока:
- работать только над вопросами и результатами этого блока;
- не смешивать его с другими блоками;
- не строить инфраструктуру без прямой исследовательской пользы;
- сохранять компактные агрегаты в `data/interim/eda2/` или `data/processed/eda2/`, документы и отчёты — в `docs/research/eda2/`, код — в `scripts/experiments/eda2/`;
- различать запланированный анализ, написанный код и реально полученные результаты;
- не заявлять о выполнении кода или тестов без фактического запуска и результатов.

## Методологические ограничения

До отдельного согласования не выполнять:
- отбор признаков и рейтинги IC;
- обучение предсказательных моделей;
- walk-forward-валидацию;
- торговые правила, BUY/SELL и целевые веса;
- портфельные метрики.

Не использовать трейдерские индикаторы, технические сигналы, свечные паттерны и эвристики ценового движения. Условные распределения допустимы только как описательный инструмент для генерации гипотез, не как доказательство предсказательной способности.

## Приоритет

Главный результат EDA2 — новое статистическое знание о структуре панели и проверяемые исследовательские гипотезы. Безопасность пайплайна и качество данных важны, но не должны подменять собой исследование.


## Организация данных и результатов (уточнение пользователя, 2026-11-26)

- `data/` — рабочие данные и машинные артефакты: панели, промежуточные расчёты, CSV/Parquet/JSON, матрицы и технические metadata.
- `docs/` — агрегированные результаты, которые Research Agent должен читать и анализировать: итоговые отчёты, компактные сводные таблицы, интерпретации, выводы и гипотезы.
- Для EDA2 машинные результаты блока сохраняются в `data/interim/eda2/block_XX/` и при необходимости `data/processed/eda2/block_XX/`.
- Читаемые агрегированные результаты каждого блока сохраняются в `docs/research/eda2/results/block_XX/`.
- Не сохранять единственный итоговый отчёт в `data/processed/`: пользователь ожидает содержательные результаты для анализа в `docs/`.
- Не копировать в `docs/` тяжёлые сырые/построчные артефакты. Переносить туда только агрегаты и отчёты, необходимые для исследовательской интерпретации.


## Результат блока 3 (запуск пользователя, 2026-11-25)

- 5,489 дат доходностей, 214 бумаг, 196,663 наблюдения доходности.
- 5,390 валидных пар из 22,791 возможной пары.
- Pearson: среднее 0.246528, медиана 0.239503, Q05 -0.038613, Q95 0.544622, доля отрицательных пар 7.885%.
- Spearman: среднее 0.258747, медиана 0.253126, Q05 -0.012481, Q95 0.554494, доля отрицательных пар 6.289%.
- Первичный вывод: положительная межбумажная зависимость выражена; ранговая оценка немного выше линейной. Это описательная статистика, не причинность и не прогноз.
- Спектральная часть не рассчитана: строгий критерий потребовал, чтобы у каждой бумаги были конечные корреляции со всеми 213 остальными; полный поднабор оказался пустым. Это ограничение текущего способа построения спектра, а не доказательство отсутствия общей компоненты.
- Не подменять исследование аудитом пропусков. Следующий адресный вопрос блока 3 — выбрать статистически корректную спектральную оценку при разреженной pairwise correlation matrix, не выдавая искусственно заполненную матрицу за наблюдаемую.
- Скрипт обновлён: отчёт и компактные агрегаты теперь публикуются в `docs/research/eda2/results/block_03/`; машинные и построчные файлы остаются в `data/interim/eda2/block_03/`.
