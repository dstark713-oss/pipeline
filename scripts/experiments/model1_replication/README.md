# model1 replication on pipeline PIT TOP50

Run from repository root:
    python scripts/experiments/model1_replication/run_replication.py --skip-backtest

Then aggregate the walk-forward statistics:
    python scripts/experiments/model1_replication/analyze_wf.py

The aggregate report is written to data/interim/model1_replication/wf_statistical_summary.json and key metrics are printed to the console. It contains fold-level mean, median, dispersion and quantiles, raw-versus-calibrated fold wins, and the pooled OOS metrics already calculated by the runner.

Run unit tests with:
    python -m pytest scripts/experiments/model1_replication/tests/ -q

The script reads data/processed/moex_daily_adjusted.sqlite (adjusted_daily_bars) and data/processed/top50/top50_panel.parquet read-only. Outputs go to data/interim/model1_replication/ and are not committed.

Copied from model1: feature formulas/windows, H=5 Triple Barrier (TP=1.5 sigma, SL=1.0 sigma, volatility window 20), two CatBoost classifiers (500 iterations, depth 6, learning rate 0.05, L2 3, min_data_in_leaf 20, seed 42), isotonic calibration, expanding WF (3-year initial train, 6-month retrain/test, 10 calendar-day purge), score P(TP)*(1-P(SL)), N grid 4..8, correlation window 20/threshold 0.8, breadth EMA20, costs 3+3 bps.

PIT adaptation: feature warmup uses full observed security history; rows enter the model only when the security belongs to PIT TOP50 on signal date and bar_available=1. No forward-fill. OHLC selects one complete board row, TQBR first and EQBR fallback; adjusted volume/value are summed across boards. Breadth uses current PIT TOP50 members.

## Calibration decision

The current isotonic calibration is inherited from model1 but is fit on predictions generated by a model that was trained on those same rows. This is not an independent calibration procedure. In the completed 38-fold run, raw predictions beat calibrated predictions on both LogLoss and Brier in all 38 folds for both TP and SL. Therefore calibrated probabilities are not accepted for the agent tool. The agent-facing tool should use raw model outputs/scores; do not describe them as calibrated probabilities.

The calibrated metrics remain in the WF report only as a diagnostic comparison. Do not use the calibrated columns as the production score.

## Scope of this experiment

This is a model replication and agent-tool quality check, not a portfolio strategy evaluation. The relevant evidence is out-of-sample statistical quality and stability: ROC-AUC, PR-AUC, LogLoss, Brier, and their variation across walk-forward folds. Sharpe/CAGR/MDD, portfolio selection N, turnover and exposure are not acceptance criteria for the agent tool.

Important inherited implementation details are recorded in run_metadata.json: N selection, breakout rolling high/low including current bar, 10-calendar-day purge, and disjoint adjacent OOS test blocks. model1's market.py is not called by its feature pipeline, so it is not added here.

No local dataset execution is performed by the authoring step. Run the WF locally, then run analyze_wf.py and share wf_statistical_summary.json for review.
